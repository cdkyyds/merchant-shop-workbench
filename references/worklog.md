# 工作日志

用户看不懂工具调用，只看得懂“这次做了什么、哪些商品、结果如何、花了多少”。每次操作结束都要产出这样一条日志。

## 一条日志的结构

```
## 14:32 下架无流量商品 37 件
- 动作：下架
- 店铺：小哈百货助手
- 数量：37
- 结果：成功 35，失败 2，跳过 0
- 费用：上游按小尊宝规则扣费（本技能不代收）

| 商品ID | 商品名称 | 结果 | 说明 |
|---|---|---|---|
| 1028384205374 | 夏日短袖… | 成功 | |
| 1028351551164 | 冰丝裤… | 失败 | 商品已下架 |
```

## 硬性规则

1. 数字（数量、成功/失败）必须来自工具返回，不允许编造；
2. 失败行必须有原因，原因原样来自工具返回的 `message`；
3. 明细列固定：商品ID、商品名称、结果、说明；商品多时先给全部失败项，再给成功项；
4. 费用只写“上游按各自规则扣费”，不要写具体金额，除非工具明确返回；
5. 删除类的日志必须带“删除不可恢复”。

## 持久化

Agent 可以用命令把日志写入本地文件，便于用户以后查：

```bash
python scripts/skill.py worklog \
  --action 下架 --shop 小哈百货助手 --count 37 \
  --result "成功35 失败2" \
  --detail-json '[{"goodsId":"1028384205374","goodsName":"夏日短袖","result":"成功","message":""},{"goodsId":"1028351551164","goodsName":"冰丝裤","result":"失败","message":"商品已下架"}]'
```

- 默认写入 `worklogs/YYYY-MM-DD.md`；
- 可用 `--dir` 指定目录；
- 每次调用追加一条，不覆盖历史。

## 不要做什么

- 不要把工具原始 JSON 直接丢给用户当日志；
- 不要把预览当成结果（“准备下架 37 件”不是“已下架 37 件”）；
- 不要在没有拿到任务结果前写“成功”。
